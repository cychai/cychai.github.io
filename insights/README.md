# 研究与洞察维护说明

## 目录结构

```text
insights/
├── index.html                 # 唯一内容入口：专题研究 + 行业交流与社会实践
├── research/
│   ├── index.html             # 兼容旧地址，跳转到上级专题研究
│   └── <内容名称>/
│       ├── index.html         # 报告正文
│       ├── assets/            # 报告专属脚本和图片
│       └── _shared/           # 报告专属字体和公共库
└── sharing/
    ├── index.html             # 兼容旧地址，跳转到上级分享区
    └── <内容名称>/            # 后续本地分享页面
```

## 新增调研

1. 在 `research/` 下创建语义明确的英文目录，例如 `agent-platform-2026/`。
2. 将报告主文件命名为 `index.html`。
3. 把报告依赖的图片、脚本和字体放在该报告自己的目录中。
4. 在 `insights/index.html` 的“专题研究”中增加内容卡片。
5. 将新文章的规范 URL 加入根目录 `sitemap.xml`。

如果源页面位于 `investment` 工作目录，应同步复制报告的完整目录，而不是只复制 HTML。当前 Bright Data 与 Genspark 报告均以该目录中的字体、脚本和图表资源为准。

## 新增分享

1. 只有外部报道或公开视频时，直接在 `insights/index.html` 的“行业交流与社会实践”中增加链接。
2. 有完整本地 HTML 内容时，在 `sharing/` 下创建独立目录并使用 `index.html` 作为入口。
3. 分享条目按时间倒序排列。
4. 首页不重复展示分享列表，确保每项内容只有一个站内入口。

## 发布检查

- 所有站内链接使用相对路径。
- 每个目录入口均命名为 `index.html`。
- 本地资源不得引用电脑绝对路径。
- 独立页面设置绝对 `canonical` 地址，并同步维护根目录 `sitemap.xml`。
- 推送到 GitHub 后检查主页、洞察页和正文页面是否均可访问。
